# ペルソナとユースケース

Mathscope を誰の、どんな場面のために作るかを決める。機能の優先順位は、ここに書いた主ペルソナとユースケースで判断する。

2026 年 10 月に、5 つの視点（学習者側・教える側・プロダクト・初見の UX 検証・反論役）で検討した結果をまとめた。利用の実態はまだ測っていないため、すべて仮説として扱い、「検証の方法」で確かめる。

## 位置づけ

| 用途 | 強い道具 | Mathscope |
|---|---|---|
| グラフを描く | Desmos | 勝てない |
| 作図・数式処理 | GeoGebra、Wolfram Alpha | 勝てない |
| 答え・途中式を出す | Photomath、ChatGPT などの AI | 勝てない。競わない |
| 体系的な解説 | 教科書、解説サイト | 勝てない |
| **初めて出会う概念を、動かして「こういうことか」とつかむ** | 決定版がない | **ここで勝つ** |

Mathscope が担うのは、答えを出すことではなく、概念の意味を図でつかむこと。UX 検証で一番うまくいったのも「固有値の意味を知りたい」で、図を動かすだけで目的を果たせた。逆に「解き方の手順を知りたい」は果たせなかった。

## ペルソナ

### 主ペルソナ: 習ったばかりの概念がピンとこない高校 1〜2 年生

- **学年と範囲:** 高 1〜2。数 I（2 次関数・三角比）、数 II（三角関数・指数対数・微分積分）、数 B・C（数列・ベクトル・複素数平面）を習っている途中
- **場面:** 授業の直後や家での復習。先生が式を動かして見せた、または配ったリンクをもう一度開く
- **端末:** スマホが中心。式を自分で打つことは少なく、リンクで開いて触る
- **来る経路:** 先生・塾講師が渡したリンク、SNS で流れてきた図。検索からはまだ来られない（下の「検索について」）
- **欲しいもの:** 「この文字を変えるとこう動く」が目で分かること
- **嫌なこと:** 登録、広告、長い動画、式を打たされること

演習中の高 3 受験生を主にしない理由は 2 つ。受験生が詰まる三角関数の変形・積分・不等式は、式変形タブがまだ扱えない。途中式の説明では AI のほうが強い。

### 届ける人: 授業で動きを見せる高校の数学教員

主ペルソナに届く経路は、今は教員と SNS のリンクしかない。そのため教員は「副」ではなく、**最初に満足させる相手**として扱う。

- **場面:** 授業の導入の数分間、プロジェクターや大型モニタで、式を動かして見せる。授業のあとに、同じ状態のリンクを生徒に配る
- **端末:** 教室の PC 1 台と、プロジェクター
- **困りごと:** GeoGebra は準備に手間がかかり、生徒には機能が多すぎる。教室の後ろの席から文字が読めない
- **要るもの:** 開いた瞬間に準備した状態が出るリンク、大きな文字、余計な部分を隠した表示

塾講師（生徒と横並びでタブレットを見る）と、記事に図を貼る発信者も同じ機能で拾える。ただし記事への埋め込みのような、発信者だけが要る機能は後回しにする。

### 第 3 ペルソナ: 定理を図で確かめ直す大学 1〜2 年生・学び直しの社会人

- 線形代数（固有値・対角化）、確率統計（中心極限定理・ベイズ）、テイラー展開などを、試験前や仕事の前に確かめる
- 定理集にある高校の範囲外の定理（線形代数・整数論・イェンセンの不等式など、全体の約 3 割）は、この人に向けたもの
- PC で、定理名を知った上でサイト内を検索して使う。専用の機能は作らない

### 狙わない人

| 人 | 理由 |
|---|---|
| 解き方・手順を知りたい受験生 | 例題は答えだけで手順がない。手順の説明は AI と競うことになる |
| 答えだけ欲しい人 | 撮影解答や、任意の式を完全に解く機能は作らない |
| 中学生以下 | 負の数や文字式の導入は扱わない |
| 大学 3 年以上・研究者 | 証明・厳密さ・高度な計算は Wolfram、GeoGebra の領域 |
| 授業を運営したい教員 | クラス管理・課題配布・採点は作らない。見せることと配ることだけ |

## ユースケース

成功は観測できる行動で定める。「分かった」かどうかは直接は測れないため、操作した・続けて見た・また来た、を代わりの指標にする。

### UC1 授業直後に、配られたリンクで概念を見直す（主ペルソナ・最優先）

- **流れ:** 先生のリンクをスマホで開く → 図やスライダーを動かす → 関連する定理やタブに移る
- **成功の指標:** 開いた人のうち、スライダーやドラッグを操作した割合。別のタブ・定理へ移った割合
- **今できること:** 定理 77 個すべてに動かせる図がある。グラフは文字が自動でスライダーになる
- **足りないこと:**
  - スマホで見出しの式がカードからはみ出る。図が小さく、指でドラッグしにくい
  - グラフタブで、スライダーを動かすとグラフが画面外に出る
  - 図の凡例がなく、どの線がどの式か分からない図がある
  - 定理から関連タブへのリンクが 77 個中 21 個だけ

### UC2 授業の導入で、式を動かして見せる（届ける人・最優先）

- **流れ:** 授業前に状態を作ってリンクを保存する → 授業で開いて映す → 動かしながら説明する → 同じリンクを生徒に配る
- **成功の指標:** リンクの共有ボタンが押された回数。共有されたリンクから開かれた回数
- **今できること:** タブ・式・定理は URL で指定できる（`#graph?f=…`、`#theorems?q=…`）
- **足りないこと:**
  - スライダーの値・表示範囲・式変形の手数が URL に残らない。「この状態」を配れない
  - 「リンクをコピー」がない
  - 全画面・発表用の表示がなく、目盛りなどの文字が小さい
  - 明るい／暗い表示を画面上で切り替えられない
  - 放物線の頂点に印と座標が出ない

### UC3 SNS で流れてきた図から入る（主ペルソナの入口）

- **流れ:** SNS のリンクを開く → トップのアニメーションや図を眺める → どこかのタブを触る
- **成功の指標:** トップから別のタブへ移った割合
- **今できること:** トップに 7 種類のアニメーション、できることのカード、定理のカードがある
- **足りないこと:**
  - アニメーションを押しても何も起きない。一番目を引くものに入口がない
  - どのリンクを共有しても、SNS のプレビューが同じ
  - スマホのトップが縦に長く、定理のカードに図がない

### UC4 名前を知っている定理を、図で確かめ直す（第 3 ペルソナ）

- **流れ:** 定理タブで名前を検索 → 図を動かす → 条件と使いどころを読む
- **成功の指標:** 検索から定理を開いた割合。検索が 0 件だった語
- **今できること:** 名前・別名・使いどころで検索できる。固有値の図は UX 検証で一番よかった
- **足りないこと:**
  - 単元名（平行移動、二次関数など）や英語（eigen など）で探すと 0 件。0 件のときに次の行き先を示さない
  - 条件があるのは 30 個、例題があるのは 38 個だけ
  - 見出しの式とホームのカードの式がずれている定理がある（対角化と Av=λv）

### UC5 初めての式を、自分で入れて動かす（主ペルソナ・PC）

- **流れ:** 教科書の式をグラフタブに打ち込む → 文字を動かす
- **成功の指標:** 入力が読み取りエラーなく通った割合
- **今できること:** 普段の書き方（x²、√、sin 2x、全角）も LaTeX も通る
- **足りないこと:** スライダーの範囲が -5〜5 で固定。スマホで式を打つのはまだ重い

## 検索について

今の URL は `#` 以降で画面を切り替えるだけで、Google は定理ごとのページとして扱わない。タイトルと SNS のプレビューも全ページで共通になる。検索から来てもらうには、定理ごとの静的なページの書き出しとサイトマップが要る。これは今ある作業の中で一番重い。

「〇〇の定理 わかりやすく」のような検索は、強い解説サイトが上位を占めている。そのため検索で集めることは当面の目標にしない。まずリンクで届く経路（UC1〜UC3）を固め、検証で伸びが見えたら静的ページを検討する。

## 判断の基準

1. **主ペルソナがスマホで、リンクから開いてすぐ触れるか。** 見栄え（トップのアニメーション）は入口の役目
2. **教員が準備した状態を、そのまま映して配れるか。** 共有の改善は、主ペルソナ同士の共有にも効く
3. 入力は普段の書き方を優先する。LaTeX は書ける人のための追加
4. 1 画面で「主張を見る → 動かす → 次に移る」がつながる
5. 答え・手順を出す方向には広げない

## 次にやること（優先順）

| 順 | 内容 | 効くユースケース |
|---|---|---|
| 1 | 状態をすべて URL に残す（スライダーの値・表示範囲・手数）。「リンクをコピー」 | UC2、UC1 |
| 2 | スマホの表示を直す（式のはみ出し、図の大きさ、グラフが画面外になる問題） | UC1 |
| 3 | 発表用の表示（パネルを隠して文字を大きく）と、明るい／暗いの切り替え | UC2 |
| 4 | 匿名のアクセス解析を入れる（下の「検証の方法」） | すべて |
| 5 | 図の凡例・頂点の印、定理と関連タブのリンクを増やす | UC1、UC2 |
| 6 | 検索 0 件のときの案内、単元名・英語での検索 | UC4 |
| 後回し | 定理ごとの静的ページ、記事への埋め込み、式変形の範囲拡大 | — |

## 検証の方法

個人で回せる範囲に絞る。

- **匿名のアクセス解析:** Cookie を使わない GoatCounter などを入れ、`#` 以降の画面ごとに数える。見るのは、入口の画面、スライダー操作の有無、共有ボタンの回数、検索 0 件の語
- **教員 2〜3 人への聞き取り:** 授業で 1 回使ってもらい、準備にかかった時間と、映したときに困った点を聞く。未成年への聞き取りはしない
- **SNS への投稿:** 定理の図をリンクつきで投稿し、どんな人が反応するかを見る
- **判断の基準（先に決めておく）:** 解析を入れてから 3 か月で、
  - 開いた人のうちスライダーかドラッグを操作した人が半分未満なら、UC1 の図の作りを見直す
  - 共有されたリンクからの訪問がほとんどなければ、「教員から届く」という経路の仮説を見直す
